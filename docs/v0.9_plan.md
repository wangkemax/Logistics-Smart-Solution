# v0.9 — Assumption Governance + 参数库

## 目标
让所有业务假设**显式化、可追溯、可覆盖、有依据**，不再散落在 hardcoded dict 和日志里。

---

## 一、Assumption Registry（假设注册表）

### 1.1 新数据库表 `assumptions`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK |  |
| run_id | String FK | 关联 pipeline_id |
| version_id | Integer | **【P0新增】假设版本号，支持回滚 |
| field_key | String | 字段名（sku_count 等） |
| assumption_value | String | 假设值 |
| assumption_rule | String | 业务依据描述 |
| source | String | extracted / manual_input / default_fallback |
| source_type | Enum | **【P0新增】SYSTEM_DEFAULT / LLM_INFERRED / USER_MODIFIED |
| confidence | Float | 置信度 0-1 |
| is_overridden | Bool | 用户是否手动覆盖 |
| validated | Bool | 是否通过行业基准校验 |
| context_tags | JSONB | **【P0新增】条件假设边界（如 {"warehouse_height_gt": 12}） |
| impact_factors | JSONB | **【P0新增】该假设影响的成本参数列表 |
| effective_date | DateTime | **【P1新增】假设生效日期，用于时间效力校验 |
| created_at | DateTime |  |

### 1.2 AssumptionSchema（Pydantic）

```python
@dataclass
class Assumption:
    field_key: str
    value: str
    rule: str                    # assumption_rule 说明
    source: str                  # extracted | manual | default
    source_type: AssumptionSourceType  # 【P0新增】SYSTEM_DEFAULT | LLM_INFERRED | USER_MODIFIED
    confidence: float           # 0.0-1.0
    is_overridden: bool = False
    validated: bool = False
    benchmark_ref: str = ""     # 参考哪个基准
    context_tags: dict = field(default_factory=dict)  # 【P0新增】条件边界
    impact_factors: list[str] = field(default_factory=list)  # 【P0新增】影响哪些参数
    effective_date: datetime | None = None  # 【P1新增】时间效力
```

### 1.3 AssumptionService（新增）

```
backend/services/assumption_service.py

职责：
- register_assumption(run_id, field_key, value, rule, source)
- override_assumption(run_id, field_key, new_value, new_rule)  → is_overridden=True
- validate_assumption(assumption) → (valid: bool, warning: str)
- get_assumptions_for_run(run_id) → list[Assumption]
- derive_from_benchmark(field_key, industry, region) → Assumption
```

## 七、测试场景（扩展至 15+ 测试）

**【P2测试扩展】** 原计划3个测试严重不足，扩展为：

| 测试文件 | 测试内容 |
|---------|---------|
| `test_assumption_service.py` | 注册/覆盖/版本回滚/上下文标签 |
| `test_assumption_qa.py` | 7条QA规则 + 互斥校验 + 时间效力 |
| `test_parameter_service.py` | 多键匹配优先级权重/离群值检测 |
| `test_assumption_range_estimate_hook.py` | **【P1新增】** override_by_assumptions Hook 不破坏原逻辑 |
| `test_assumption_concurrent.py` | **【P2新增】** Streamlit多Session下无数据串扰 |
| `test_assumption_versioning.py` | **【P0新增】** 版本回滚功能 |
| `test_golden_dataset_extraction.py` | **【P2新增】** 20个真实RFP基准测试集 |

**核心边界case：**
1. P1 字段缺失时自动注册 assumption，source=default
2. 用户手动输入，覆盖后 is_overridden=True，version_id+1
3. 基准校验 — sku_count=100（不合理值）→ QA Warning
4. 跨行业校验 — FMCG 项目用了 AUTOMOTIVE 假设 → Error
5. CSV 回退 — 删掉某条 CSV，行业通用 fallback 仍可用
6. **互斥校验** — 同时假设"全自动化"+"低人力成本" → Error
7. **时间效力** — effective_date 超过6个月的假设 → Warning
